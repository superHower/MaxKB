## 本版定位

主线是“能把 Agent 做成业务系统的全栈工程师”。主项目以企业级多模态 Agent 平台呈现，用 Harness 串起任务编排、Skills、工具执行、上下文管理和质量反馈；CRM 项目体现真实业务集成与可靠性经验。

备战材料中的重点已经对应到简历：

| 方向 | 简历中的表达 |
| --- | --- |
| Agent Harness | 推理与执行循环、工具约束、沙箱、递归上限、执行追踪 |
| Skills / 程序性记忆 | 技能包、渐进式加载、参数注入、业务流程复用 |
| 多 Agent | 主 Agent、业务子任务、子应用调用、上下文隔离 |
| Context / Memory | 会话状态、历史消息、知识与技能组合、文件和表单传递 |
| RAG / Agentic RAG | 混合检索与证据链；多步检索、Deep Research 的技术理解 |
| 多模态 | 图像理解、文档提取、ASR / TTS、IVR 与工作流集成 |
| Evaluation / 数据 | 版本化测试集、Judge、回归、Badcase、合成数据方法 |
| 自进化 / 前沿方法 | 轨迹反馈、技能修订、Verifier、SFT / DPO / GRPO、世界模型 |

## 建议准备的四个深挖故事

1. **Harness：** 一次任务怎样从模型决策进入工具执行，再把结果回填？执行失败、超出循环次数或工具不可用时如何处理？
2. **Skills：** 工具提供原子能力，Skill 如何组织步骤？技能何时加载、参数如何传入、怎样验证修改后仍然有效？
3. **多模态与上下文：** 图片、语音和文件如何进入同一条任务链？父子应用怎样传递文件与表单？哪些状态需要隔离？
4. **评测反馈：** 为什么检索命中仍可能答错？怎样区分检索、上下文组装、生成和评分器的问题，再把失败案例固化进回归集？

## 数字速查

- 客服样本共 36 条：售前 14 条、售后 14 条、边界 8 条，来自知识库内容构建。
- 8 条边界样本复测，报告标记 5 条评分退化案例；这说明评测链路能识别差异，不代表故障率或模型能力提升。
- 售前 / 售后集：检索命中率均为 100%，答案正确性 0.907 / 0.921（Judge，0～1）。
- 边界集复测：Judge 均分 0.683 → 0.492，检索指标不变；8 条匹配题中 5 条被标记为回归。
- 线上 Badcase 10 条，归因到 3 个节点：意图分流 5 条、售后信息收集 3 条、订单物流提示 2 条；对应 3 个改进方案。闭环回归功能已上线，但这些 Badcase 还没有实际走完关闭流程，面试中不要说“已修复”。
- 评测后端约 4500 行（apps/evaluation + rag_eval）；28 个单元测试。
- 原简历的大规模文档数与业务效果数字可以在有对应业务统计时补充，本版以技术机制与具体产物承担主要吸引点。
