# 智能体评测建设路线

## 目标

将现有的知识库命中测试逐步扩展为完整的智能体质量评测体系，同时保留知识库检索测试作为基础能力。智能体详情页的独立测评入口先隐藏，后端接口和历史数据暂不删除。

## 分阶段交付

| 阶段 | 目标 | 主要交付物 |
| --- | --- | --- |
| 0 | 调整入口 | 隐藏智能体测评前端路由和菜单，保留 API |
| 1 | 完整日志 | 统一保存问题、答案、上下文、版本、耗时、Token、反馈 |
| 2 | 真实采样 | 从聊天日志筛选样本，生成可标注测评集 |
| 3 | 人工标注 | 标注答案、引用、无答案识别、忠实度和 Badcase 原因 |
| 4 | 自动评估 | 接入规则评估和可选 Judge 模型 |
| 5 | 离线回归 | 固定测评集，对提示词、模型、切片和检索配置做回归 |
| 6 | 线上质量 | 统计解决率、转人工率、成本、延迟等业务指标 |
| 7 | 灰度实验 | 支持按用户或会话分组比较版本 |
| 8 | Badcase 闭环 | 周期性抽检、归因、修复、回归和灰度 |

## 实施原则

1. 先补齐数据链路，再开发评分器。
2. 自动评分必须保留理由，并允许人工修正。
3. 检索指标和回答指标分开统计，避免把“召回正确”当成“回答正确”。
4. 每次评测保存应用、模型、提示词、知识库、切片和检索参数快照。
5. 新功能优先复用现有 ChatRecord、投票、知识库命中和 evaluation 模块。

## 依赖关系

```text
完整日志 -> 真实样本 -> 人工标注 -> 自动评估 -> 离线回归
                                      -> 线上指标 -> 灰度实验
线上低分/反馈 -> Badcase 归因 -> 数据或配置修复 -> 离线回归
```

## 第一批开发范围

先完成阶段 0～3：隐藏入口、补齐日志字段、真实日志采样、标注工作台。阶段 4 之后依赖样本和标注数据，不能在数据不完整时直接上线自动评分。

## 验收标准

- 每条聊天记录可以追溯到应用版本、知识库、模型和最终上下文。
- 可以按条件从真实日志采样并生成测评集。
- 标注结果可保存、修改、审计，并能导出。
- 旧智能体测评历史仍可查询，隐藏入口不影响现有 API。
