# 智能体评测实施拆解

## 阶段 A：入口和基础接口

### 后端

- 保留 `apps/evaluation` API 和历史数据。
- 增加评测事件、样本、标注、评估结果、实验组模型。
- 增加按应用、时间、反馈、状态和采样原因查询接口。

### 前端

- 隐藏应用详情页的 `evaluation` 路由和菜单入口。
- 不删除组件和 API，避免历史链接和权限检查报错。
- 在知识库侧新增“质量评测”入口，先展示日志采样和样本列表。

## 阶段 B：日志完整化

1. 梳理所有聊天执行路径，统一写入评测事件。
2. 从工作流详情中提取检索候选和最终上下文。
3. 记录应用、模型、提示词、知识库和检索参数快照。
4. 补充 Token、费用、耗时、投票和转人工字段。
5. 对旧记录允许字段缺失，并在界面标记“不可评估”。

验收：随机抽查聊天记录，能够从问题追溯到最终上下文和版本配置。

## 阶段 C：真实日志采样

提供筛选条件：

- 时间范围；
- 应用/知识库；
- 点赞、点踩、无反馈；
- 是否追问、转人工、无命中；
- 延迟和成本阈值；
- 随机比例和数量上限。

导入样本时去重，同一聊天记录不能重复进入同一测评集。允许人工删除或补充样本。

## 阶段 D：人工标注工作台

页面同时显示问题、答案、最终上下文、引用、反馈和版本信息。支持快捷标注、批量操作、备注、筛选未标注和导出。

标注完成后生成冻结版本，作为离线回归集。后续修改标注必须产生新版本，不能静默覆盖历史结果。

## 阶段 E：自动评估器

先实现不依赖模型的规则指标，再接入可选 Judge：

1. 规则：响应时间、Token、成本、是否有上下文、是否转人工、引用 ID 完整性。
2. 检索：命中率、MRR、召回率和精度。
3. Judge：答案正确性、引用相关性、无答案识别、忠实度。

Judge 输出必须采用结构化 JSON，并保存模型、提示词、版本和原始理由。自动结果与人工结果分开保存。

## 阶段 F：离线回归

对冻结测评集运行指定应用版本，保存每条样本结果和整体报告。支持选择基线并比较：正确性、引用、无答案、忠实度、检索、延迟、Token 和成本。

触发方式：手动、发布前检查、CI 或定时任务。提示词、模型、Embedding、切片、Rerank、权限和工作流变化都应触发回归。

## 阶段 G：线上看板与灰度

- 先提供只读趋势和分组统计；
- 再增加实验配置和会话分流；
- 实验结果达到最小样本量后才允许结论；
- 灰度期间保留版本快照和异常样本。

## 阶段 H：Badcase 闭环

每周自动生成候选集：低分、点踩、转人工、无答案、超时、高成本和随机样本。审核人员按数据、检索、生成、提示词、模型、权限、用户问题归因，并填写修复建议。

修复完成后必须：

1. 更新离线测评集或知识库；
2. 重新运行回归；
3. 通过后进入灰度；
4. 在下一周期检查线上指标。

## 风险与边界

- 没有最终上下文时不能计算忠实度和引用准确率。
- 没有人工或可靠标准答案时，答案正确性只能作为待审核结果。
- 费用依赖模型价格配置，必须记录价格版本。
- 评估器本身变化会影响历史分数，报告必须保存评估器版本。
