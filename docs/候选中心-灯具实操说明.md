## 操作顺序和审批表单

1. 保存草稿，打开详情核对 Diff、基线版本、风险和全部冻结题目。
2. 点击“开始验证”。每题分别调用模型生成基线回答与候选回答，再由 Judge 评分；8 题通常需要约 32 次模型调用。
3. 展开验证报告，检查硬门禁、逐题答案、Judge 原因、延迟与成本。缺少数据或硬门禁失败不能豁免。
4. 未通过时点击“修改候选”，保存新修订后重验；也可以填写原因“驳回”。历史修订和报告保留。
5. 所有硬门禁通过后，点击“人工批准”。“影响范围”写实际覆盖的节点、业务和局限；“回滚点”选当前生产版本 `01a161ab-60f2-7b10-ae53-3382c0d06159`。如果报告只有业务类别退化，逐类填写经审核的豁免原因，不能笼统填“测试通过”。
6. 批准后得到待发布能力版本。后续准备发布、灰度、全量和回滚是独立的受控发布流程，批准本身不切换线上版本。

本例建议的“影响范围”：仅灯具客服回答节点 System；覆盖选型、色温、调光、安装和售后问答。离线验证使用冻结证据，不代表业务接口已执行成功，也不代表修改了意图路由或修复了召回缺失。
